# 本机验收记录

环境：macOS 27.0.1 arm64，Apple M4 Max，Python 3.11 独立环境。此记录区分工程检查、推理成功和音乐识别质量。

## 已完成

- C17 可执行文件和动态库编译成功；自写代码启用 `-Wall -Wextra -Wpedantic`。
- **29 项自动检查通过**：六个已知频率、静音/噪声弃答、反相立体声、损坏 WAV、整数参数边界、真实格式识别、重复/缓存、丢失数组重算、采样精确裁剪、禁止覆盖、缓存路径隔离、中文路径、元数据冲突、C/Python 数据一致、事件分页、人工修正保留原观察、可移植导出。
- 畸形文件、数值边界、噪声/静音/反相用 AddressSanitizer 和 UndefinedBehaviorSanitizer 构建执行，无检测错误。不是完整模糊测试。
- `pip check` 无依赖冲突；skill 校验通过。锁定模型环境为 Python 3.11，旧的 3.12 试验环境不作为默认入口。
- C 扫描实库 **2,121 个音频、1,628 个唯一文件内容、493 条重复路径，0 失败**。扫描重用已有内容元数据，仍重新读取 SHA；不是首次解码吞吐量测试。
- Beat This、CREPE 在 MPS 上、Basic Pitch 在 ONNX Runtime、CLAP 在 CPU 上实际推理成功。音频未上传。

## 测量与速度

`evaluate.py` 生成 MIDI 24/36/48/60/72/84 对应的六个正弦信号；两个算法全部返回根音。C YIN 最大误差约 **1.95 cents**，pYIN 最大约 **20.64 cents**。这个小测试只检查频率计算和低频行为，不能代表真实乐器、复音或歌曲准确率。

| 检查 | C | Python 对照 |
|---|---:|---:|
| 同一摘要，5 次新进程启动中位数 | 8.98 ms | 526.51 ms |
| 2 秒 MIDI 84 正弦音高，预热后 3 次中位数 | YIN 85.50 ms | pYIN 596.95 ms |

摘要加速来自绕过 Python/科学计算库启动；音高对照采用不同算法，不能归因为语言差异，也不能外推到神经模型速度。

## Apple 原生补充

- 实际编译 Swift 桥接，SoundAnalysis `version1` 返回 303 类声音标签；钢琴样本给出 music、keyboard_musical、piano 及铃类候选，仍有歧义。
- SpeechAnalyzer 实际运行中文本地模型。以系统语音合成的“这是一段语音识别测试。我们正在分析钢琴、鼓和低音。”作已知输入，转写汉字一致，标点和分段不同，含字词时间及备选。这不是实际人声/演唱准确率评测。
- 自动检查增加真实 SoundAnalysis 的时间坐标、分数与候选数量；模拟非 macOS 时断言不会启动 Apple 进程，缺后端显式报告不可用。没有冒充 Linux 真机测试。
- `doctor` 分开报告框架可用性、语言资源状态和旧 Speech 权限，不将 Core ML 运行时当成内置音符模型。

- Basic Pitch 的 Core ML 路径已实际运行，得到 2 个音符候选，与本例 ONNX 数量一致；只证明该样本可推理，不代表两后端在全部输入上等价。
